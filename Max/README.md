# Max — модуль транспорта для CryptoLayer

Модуль обмена текстовыми сообщениями между двумя людьми через **личные аккаунты
MAX** со сквозным шифрованием, которое выполняет само ядро [CryptoLayer](https://github.com/igmunv/cryptolayer).
Модуль реализует контракт `BaseModule` (пакет `cryptolayer-module-interface`):
вложенные `Sender.send(text)` и `Listener`, фабрика `create_session(ingester)`.

Канал связи: **неофициальный пользовательский API** MAX (WebSocket `wss://ws-api.oneme.ru`,
протокол v11) через библиотеку [vkmax](https://github.com/nsdkinx/vkmax).
**Боты и Bot API не используются вообще.**

## ⚠️ Важно: неофициальный API и условия использования

> **Этот модуль работает через неофициальный API MAX.** Официального
> пользовательского API у MAX нет, поэтому vkmax имитирует веб-клиент
> web.max.ru. Такое использование **нарушает условия использования MAX**
> и несёт **риск блокировки вашего аккаунта**. Протокол не документирован
> официально и может измениться в любой момент.
>
> **Используйте модуль на свой риск.** Автор модуля не отвечает за возможную
> блокировку аккаунта, потерю переписки или любые другие последствия.

## Как это работает

- При старте модуль логинится по токену (`login_by_token`) и держит
  WebSocket-соединение; входящие сообщения помечаются **прочитанными** примерно
  через секунду. Попытка показать **«в сети»** (`opcode 1 {"interactive":true}`) делается,
  но сервер MAX может не поднимать индикатор для неофициальных клиентов — это
  известная лимитация (см. «Ограничения»).
- Отправка: `send(text)` кладёт сообщение в очередь (макс. 1000),
  worker-поток отправляет по одному с «человеческой» случайной паузой
  (по умолчанию 2–6 секунд). Сетевые ошибки → повтор с экспоненциальной паузой
  5→120 с; ошибки авторизации/несуществующий чат → терминальная ошибка, worker
  останавливается.
- Приём: входящие push-пакеты (`opcode=128`) фильтруются по вашему диалогу и по
  отправителю (свои эхо-сообщения исключаются), текст передаётся ядру через
  `ingester`. Обрыв WebSocket восстанавливается автоматически: паузы
  5→10→20→40 с (потолок 60 с), после 5 неудачных попыток подряд — поток приёма
  останавливается с ошибкой в логе.
- Шифрование модулем не выполняется: байты шифрует и собирает ядро CryptoLayer
  (AES-256-GCM + подписи ECDSA), модуль гоняет естественный текст.

## Установка с нуля — пошагово с шаблонами команд

> Ниже — полный путь от пустого компьютера до чата. Скопируйте команды как есть,
> подставив свои значения в `<...>`.

### Шаг 0. Что понадобится

- Python ≥ 3.10, Git
- Аккаунт MAX на каждом компьютере (разные аккаунты!)
- Диалог с собеседником уже создан (напишите друг другу 1 сообщение в обычном MAX)

### Шаг 1. Скачайте этот репозиторий

```bash
git clone https://github.com/Noisy-Auto-Flare/Max-module-cryptolayer.git
cd Max-module-cryptolayer
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
# source .venv/bin/activate
pip install -r requirements-dev.txt
pip install git+https://github.com/igmunv/cryptolayer-module-interface.git
pip install -r Max/requirements.txt
```

### Шаг 2. Достаньте Token и Device ID (на КАЖДОМ компьютере — со своего аккаунта)

1. Откройте [web.max.ru](https://web.max.ru) и войдите в аккаунт.
2. **F12** (DevTools) → вкладка **Application** → **Local Storage** → `https://web.max.ru`.
3. Найдите ключи:
   - **`__oneme_auth`** — внутри хранится JSON вида `{"token":"...","...":...}`.
     **Скопируйте именно значение поля `token`** (строку без кавычек и без фигурных скобок).
     `discover_chats.py` примет и весь JSON целиком, но в CryptoLayer CLI нужно вставлять **только токен**.
   - **`__oneme_device_id`** — значение этого ключа и есть ваш **Device ID** (копируйте целиком).

Это доступ к учётной записи — не публикуйте и не передавайте. Токен ротируется при каждом перелогине — скопировали, сразу используйте.

### Шаг 3. Узнайте Chat ID (адрес диалога)

На каждом компьютере — **со своего аккаунта**:

```bash
# из корня этого репозитория, venv активирован:
python scripts/discover_chats.py --token <TOKEN> --device-id <DEVICE_ID>
```

Скрипт напечатает таблицу ваших диалогов:

```
chat_id                название/тип                             последнее сообщение
----------------------------------------------------------------------------------------------------
493588231              (DIALOG)                                 привет
22508851               (DIALOG)                                 Ола
...
```

Возьмите **chat_id** диалога с собеседником. На практике у обоих собеседников этот ID **скорее всего одинаковый** (один диалог — один ID), но проверьте на каждой стороне своим `discover_chats.py`.

**Шаблон:** `python scripts/discover_chats.py --token "только_значение_token" --device-id "ваш_device_id_целиком"`

### Шаг 4. Поставьте CryptoLayer CLI

```bash
git clone https://github.com/igmunv/cryptolayer-cli.git
cd cryptolayer-cli
./run.sh          # первый запуск — скачает сабмодули/зависимости; на Windows — через Git Bash
# после проверки, что CLI стартует — выйдите из него
```

На Windows без Git Bash — вручную (PowerShell — `&&` не работает, выполняйте по строкам):

```bash
git submodule update --init --recursive
python -m venv venv
venv\Scripts\activate
python src/modules/generate_reqs.py
python src/modules/generate_hidden_imports.py
pip install -r requirements.txt
```

### Шаг 5. Скопируйте модуль в CLI

```bash
# из репозитория модуля (пример пути):
cp -r Max/  <путь-к-cryptolayer-cli>/src/modules/Max
# Windows PowerShell:
# Copy-Item -Recurse Max C:\путь\cryptolayer-cli\src\modules\Max
```

**ВАЖНО: после копирования НЕ запускайте** `./run.sh` и `git submodule update --init --recursive` — они удалят скопированный модуль!

### Шаг 6. Установите зависимости модуля в CLI

```bash
cd <путь-к-cryptolayer-cli>
# тем же python, которым будете запускать CLI (venv активирован):
python src/modules/generate_reqs.py
python src/modules/generate_hidden_imports.py
pip install -r src/modules/common_requirements.txt
# проверка:
pip show vkmax
```

> **Если `generate_hidden_imports.py` упал с `SyntaxError: invalid syntax` на строке `import vkmax @ git+...`** — это известный баг официального сборника: генератор не понимает зависимости вида `pkg @ git+https://...` (PEP 508). Почините его один раз:
> ```powershell
> notepad src\modules\generate_hidden_imports.py
> # найдите: pkg = mod.strip().split('==')[0].split('>=')[0]
> # замените на:
> # pkg = mod.split('@')[0].split('==')[0].split('>=')[0].split('<=')[0].split('<')[0].split('>')[0].strip()
> # и добавьте проверку: if pkg: hidden_imports.add(pkg)
> # сохраните, затем снова:
> python src/modules/generate_hidden_imports.py
> ```
> Фикс войдёт в PR сборника позже; пока — этот патч центрально документирован здесь.

### Шаг 7. Запустите чат (на ОБОИХ компьютерах)

```bash
python src/cryptolayer_cli.py
```

CLI спросит по очереди:

1. **Пароль** — для шифрования локальных файлов CryptoLayer (забыли → удалите папку данных). Пароли могут быть разные.
2. **Словарь WordCoder** — выберите **ОДИНАКОВЫЙ** на обеих сторонах (например, `short_words_RU.json`). Разные словари = мусор вместо текста.
3. **Модуль** — выберите `1` (MAX).
4. **Credentials — 4 поля (адрес диалога — отдельно в Peer):**

| # | Поле | Что вписать | Пример |
|---|---|---|---|
| 1 | `Token` | `__oneme_auth` → поле `token` | `eyJhbG...` |
| 2 | `Device ID` | `__oneme_device_id` | `a1b2c3...` |
| 3 | `Мин. пауза, сек` | пусто = 2 | `Enter` |
| 4 | `Макс. пауза, сек` | пусто = 6 | `Enter` |

5. **Peer ID (in module)** — **число Chat ID из шага 3** (обязательно; это единственный адрес диалога). Одни credentials можно сохранить один раз и потом привязывать к ним много пиров.

**Шаблон заполнения (Token — только значение поля `token` из JSON `__oneme_auth`):**

```
Token: <только token, без кавычек и скобок>
Device ID: <вставьте __oneme_device_id целиком>
Мин. пауза, сек: [Enter]
Макс. пауза, сек: [Enter]
Peer ID (in module): 22508851
```

6. При **первом** соединении CLI покажет подписи — **сверьте их по телефону/лично** и подтвердите с обеих сторон (защита от MITM, пропускать нельзя). Дальше установление туннеля: в MAX-чате побегут слова — это нормально; занимает несколько минут.
7. Переписывайтесь!

## Скорость

Осознанная цена незаметности: пауза 2–6 секунд между сообщениями делает
трафик похожим на человеческий. Ядро режет данные на чанки ~100 байт, поэтому
сообщение в ~1 КБ занимает минуты. Если нужно быстрее — уменьшите паузы в
credentials, но помните про лимиты сервера и риск флуда.

Подробная семантика потерь при затяжном троттлинге — ADR-3 в [docs/DECISIONS.md](../docs/DECISIONS.md).

## Устранение неполадок

| Симптом | Что делать |
|---|---|
| `RuntimeError("MAX login failed: проверьте Token и Device ID")` + в трейсбеке `ModuleNotFoundError: No module named 'vkmax'` | Забыли шаг 6: зависимости не установлены тем python'ом, которым запускаете CLI. Повторите `generate_reqs.py` + `pip install -r src/modules/common_requirements.txt` тем же интерпретатором. |
| `Exception: login.token` в трейсбеке | Сервер отклонил токен — он протух. Токен ротируется при каждом перелогине web.max.ru. Возьмите свежий Token/Device ID (шаг 2) и введите заново (выберите `n` при вопросе про сохранённые credentials). Не держите тот же токен открытым в браузере с автоперелогином. |
| `TERMINAL send failure … Проверьте Token / Chat ID` | Чаще всего неверный Chat ID — перепроверьте `discover_chats.py` (шаг 3), перезапустите CLI. |
| Модуля MAX нет в списке CLI | Не выполнен `generate_reqs.py` после копирования, либо модуль скопирован не в `src/modules/Max`. |
| Собеседник не появляется / `Ping timeout` | Инициализацию проходят оба узла одновременно; убедитесь, что второй компьютер тоже запущен и дошёл до этого же этапа. |
| Слова приходят, но превращаются в мусор | Разные словари WordCoder — выберите одинаковый. |
| `MAX connection lost permanently` | Сеть недоступна или токен больше не действителен; проверьте и перезапустите CLI. |
| Предупреждения `op=128 for our chat lacks message/sender fields` | Возможный дрейф схемы пакетов — сообщения отбрасываются, а не доставляются вслепую (см. Ограничения). |

## Ограничения

- Только текст; файлов и медиа нет.
- **«В сети» не гарантируется:** сервер MAX может не показывать индикатор онлайн для неофициальных клиентов, даже если keepalive шлёт `{"interactive":true}`. Модуль делает best-effort (немедленный пакет + каждые 30 с), но доставка и «прочитано» — основной механизм маскировки.
- Поле отправителя (`payload.message.sender`) живо подтверждено на сервере (`contact.id` / `lastMessage.sender`), но при будущем дрейфе протокола схема фиксируется в [docs/vkmax-contract.md](../docs/vkmax-contract.md).
