# Max — модуль транспорта для CryptoLayer

Модуль обмена текстовыми сообщениями между двумя людьми через **личные аккаунты
MAX** с сквозным шифрованием, которое выполняет само ядро [CryptoLayer](https://github.com/igmunv/cryptolayer).
Модуль реализует контракт `BaseModule` (пакет `cryptolayer-module-interface`):
вложенные `Sender.send(text)` и `Listener`, фабрика `create_session(ingester)`.

Канал связи: **неофициальный пользовательский API** MAX (WebSocket `wss://ws-api.oneme.ru`,
протокол v11) через библиотеку [vkmax](https://github.com/nsdkinx/vkmax).
**Боты и Bot API не используются вообще.**

## ⚠️ Важно: неофициальный API и условия использования

> **Этот модуль работает через неофициальный API MAX.** Официального
> пользовательского API у MAX нет, поэтому vkmax имитирует веб-клиент
> web.max.ru. Такое использование **нарушает условия использования MAX**
> и несёт **риск блокировки вашего аккаунта**. Протокол не документирован
> официально и может измениться в любой момент.
>
> **Используйте модуль на свой риск.** Автор модуля не отвечает за возможную
> блокировку аккаунта, потерю переписки или любые другие последствия.

## Как это работает

- При старте модуль в отдельном потоке поднимает цикл asyncio и логинится
  по токену (`login_by_token`). Свой id берётся из ответа логина.
- Отправка: `send(text)` мгновенно кладёт сообщение в очередь (макс. 1000),
  worker-поток отправляет сообщения по одному с «человеческой» случайной паузой
  (по умолчанию 2–6 секунд). Сетевые ошибки → повтор с экспоненциальной паузой
  5→120 с; ошибки авторизации/несуществующий чат → терминальная ошибка, worker
  останавливается.
- Приём: входящие push-пакеты (`opcode=128`) фильтруются по вашему диалогу и по
  отправителю (свои эхо-сообщения исключаются), текст передаётся ядру через
  `ingester`. Обрыв WebSocket восстанавливается автоматически: паузы
  5→10→20→40 с (потолок 60 с), после 5 неудачных попыток подряд — поток приёма
  останавливается с ошибкой в логе.
- Шифрование модулем не выполняется: байты шифрует и собирает ядро CryptoLayer,
  модуль гоняет естественный текст.

## Настройка

### 1. Token и Device ID

Получите из браузера на [web.max.ru](https://web.max.ru):

1. Войдите в свой аккаунт MAX в браузере.
2. Нажмите **F12** (DevTools) → вкладка **Application** → **Local Storage**
   → `https://web.max.ru`.
3. Найдите ключи:
   - **`__oneme_auth`** — значение этого ключа и есть ваш **Token**;
   - **`__oneme_device_id`** — значение этого ключа и есть ваш **Device ID**.

Оба значения копируйте целиком. Это доступ к вашей учётной записи: не
публикуйте их и не передавайте никому.

> Совет: возьмите Token и Device ID с того аккаунта, который будет работать
> на этой машине. Собеседнику нужны его собственные значения для его копии
> модуля.

### 2. Chat ID (адрес диалога)

Chat ID — числовой идентификатор диалога с собеседником. Узнайте его
скриптом discovery:

```
python scripts/discover_chats.py --token <TOKEN> --device-id <DEVICE_ID>
```

Скрипт залогинится и напечатает таблицу доступных диалогов
(chat_id — название/тип — последнее сообщение); токены в выводе маскируются.
Найдите диалог с собеседником и возьмите его chat_id.

### 3. Credentials

Модуль запрашивает пять полей (по порядку):

| # | Поле | Что вписать |
| --- | --- | --- |
| 1 | `Token` | значение `__oneme_auth` из LocalStorage web.max.ru |
| 2 | `Device ID` | значение `__oneme_device_id` из LocalStorage web.max.ru |
| 3 | `Chat ID` | числовой id диалога с собеседником (см. `scripts/discover_chats.py`) |
| 4 | `Мин. пауза, сек` | нижняя граница паузы между отправками; пусто = 2 |
| 5 | `Макс. пауза, сек` | верхняя граница; пусто = 6 |

Правило адресата одно: **Chat ID авторитетен**. Аргумент `user_id` от оболочки
валидируется на непустоту, но при расхождении с Chat ID приоритет у Chat ID.

## Скорость

Это осознанная цена незаметности: пауза 2–6 секунд между сообщениями делает
трафик похожим на человеческий. Ядро режет файлы на чанки ~100 байт, поэтому
сообщение в ~1 КБ — это около десятка чанков, то есть **минуты** на одно
полное сообщение. Если нужно быстрее — уменьшите паузы в credentials, но
помните про лимиты сервера и риск флуда.

Подробная семантика потерь при затяжном троттлинге описана в ADR-3
([docs/DECISIONS.md](../docs/DECISIONS.md)).

## Устранение неполадок

| Симптом | Причина и что делать |
| --- | --- |
| `RuntimeError("MAX login failed: проверьте Token и Device ID")` при старте | Неверный или протухший Token / Device ID, либо нет сети. Перевыпустите значения из LocalStorage web.max.ru (см. выше) — они меняются при перелогине. Проверьте, что скопировали значения целиком. |
| Лог: `TERMINAL send failure … остановка worker'а. Проверьте Token / Chat ID` | Терминальная ошибка отправки: чаще всего неверный Chat ID (диалога не существует) либо отозванный токен. Worker остановлен, очередь очищена — исправьте credential и пересоздайте сессию (перезапуск модуля). |
| Сообщения уходят очень долго или не доходят до конца | Затяжные сетевые ошибки включают backoff до 120 с на попытку; при этом очередь может накапливаться. См. ADR-3 о семантике потерь. Проверьте связь; при постоянных ошибках перезапустите сессию. |
| Лог: `MAX websocket connection lost; reconnecting in N s` | Обрыв соединения. Модуль сам переподключается (паузы 5→60 с). Если после 5 неудач появляется `MAX connection lost permanently` — сеть недоступна или токен больше не действителен; проверьте и перезапустите модуль. |
| Предупреждения вида `op=128 for our chat lacks message/sender fields` | Возможный дрейф схемы пакетов протокола (поле отправителя подтверждено только по эталонным клиентам, живая сверка — см. раздел «Ограничения»). Сообщения в этот момент отбрасываются, а не доставляются вслепую. |
| Флуд-ошибки от сервера | Классифицируются как транзиентные, модуль сам ретраит с растущей паузой. Не уменьшайте паузы ниже ~1–2 с. |

## Ограничения

- v1 — только текст; файлов и медиа нет.
- Поле отправителя во входящем пакете (`payload.message.sender`) и имена
  внутренних полей чатов corroborated-but-not-live-verified: сверены с
  независимой реализацией того же протокола, но живая проверка владельцем
  (ранний чекпойнт `scripts/discover_chats.py`) ещё pending. При расхождении
  схема фиксируется в [docs/vkmax-contract.md](../docs/vkmax-contract.md).
- Точная семантика потерь при троттлинге — ADR-3 в [docs/DECISIONS.md](../docs/DECISIONS.md).

Технические подробности адаптера: [docs/vkmax-contract.md](../docs/vkmax-contract.md)
(источник истины по всем сигнатурам vkmax).
